# 武将四技能与六项属性

当前实现面向 1920×1080、目标 60 FPS；战斗演算固定 60 Hz。地图与战斗共享 `data/unit_catalog.json` 和 `scripts/unit_catalog.gd` 的定义，魔法防御字段为 `magic_defense`，没有新增法力值。

哪吒已接入浅杏绢纸背景立绘和独立的 Q 版战斗角色，普攻使用 16 帧双段连刺。被动改为三头六臂：每段命中对主目标周围其他敌军造成该段 35% 系数的物理溅射，法相与角色分层播放。普攻累计三次命中及乾坤圈仍可叠加灼烧（最多三层、四秒）；三昧真火消耗目标身上自身施加的灼烧，提高爆发伤害。火莲焚阵在火柱爆发时结算，施法期间锁定地图行动。完整时序、数值和最新验证见 [nezha_art_v3.md](nezha_art_v3.md)。

## 操作与结算

1. **自动读条技能**：主将接近敌人、冷却结束且收招后开始读条，读条完成结算伤害。普通攻击仍独立进行，使用物攻 / 物防。
2. **手动终结技**：双方每场初始士气 50，实际击杀每名士兵增加 0.1（暂定平衡参数），上限 100。列阵结束且主将存活时，按 R 或点击按钮消耗 100 立即打断普攻、战技或移动并释放；之后能重新积累。敌方在相同条件下自动施放。不再要求开战前 70 士气、等待 8 秒或每战仅一次。
3. **地图技能**：按 Q 或技能按钮选点，预览射程和作用范围，左键释放，右键 / Esc 取消。成功释放将本队行动力置零并标记本轮行动结束；失败与取消不扣行动。不能在行军动画或战斗中施法。其他部队仍能继续行动。
4. **被动**：随武将配置自动生效，区分自身与所率全军范围。地图属性面板和战斗实际结算都使用同一结果。

士气按真实士兵战损统计：一个满编模型代表 100 人，受到部分伤害时就按剩余生命换算人数。对尸体、友军或溢出的伤害不会重复增加击杀。英雄本身不计入士兵击杀数。战斗结束保留本场统计；新战斗独立从 50 士气开始。

前三位是现有可操作部队，分别通过 1 / 2 / 3 选择。闻仲是敌方守将；姬发配置可供后续军队使用。减益、行军已通过规则测试，但这两名武将尚无玩家招募入口。

除行军外，当前地图技能射程均为 5 格、作用半径 2 格。增益与减益持续当前及下一回合，随后在新回合开始前移除；同名效果刷新持续时间，不叠加。全军效果作用于主将和兵种实体。恢复不超过部队兵力上限，并同步三个编制槽的人数。

默认朝歌测试场中，伤害、减益直接作用于对面的哪吒或闻仲部队。原战役的伤害、减益作用于商军据点守军；多格据点只结算一次，伤害不会直接改变据点归属。行军技能仍检查山河、敌方据点、友军占位与渡口通行规则，成功抵达后结束本轮行动。

## 六项属性

| 字段 | 含义与生效位置 |
| --- | --- |
| `physical_attack` | 物攻：普攻与物理技能伤害 |
| `physical_defense` | 物防：抵减物理伤害 |
| `magic_attack` | 魔攻：魔法技能伤害 |
| `magic_defense` | 魔防：抵减魔法伤害 |
| `max_hp` | 生命：战斗实体生命上限；非满编戟兵模型按人数缩放 |
| `movement` | 移动力：大地图每回合移动预算，平地每格 1 点、现有渡口通道 2 点 |

英雄、戟兵、守军英雄和守军戟兵均有完整字段。地图上的军队作为一个整体移动，采用主将最终移动力；戟兵仍有独立移动力配置，混编与各兵种限速规则留待兵种扩展。该属性不改变战斗内的跑步动画速度。

最终属性 = 基础属性 + 被动 + 尚未到期的地图增减益。基础值写入存档，附加值在使用时计算，避免读档重复叠加。普通攻击 / 技能伤害 = 对应攻击 × 技能倍率 × 100 ÷ (100 + 对应防御)，最低 1。地图伤害按相同魔法公式乘 5 换算为兵员损失，且不超过据点剩余人数。

当前移动力：哪吒 6、南宫适 6、黄天化 8、闻仲 6、姬发含被动 7。数值、技能名和倍率均集中在配置中，可继续调整。

## 存档与验证

schema 6 保存网格版本，以及武将身份、基础属性、临时效果和到期回合、本轮施法状态及受损守军。当前网格为 grid_revision 3，兼容 schema 1–5 和上一版 schema 6、grid_revision 2；旧档按稳定部队 ID 补齐默认配置，并把旧格子转换到原地图位置附近的合法陆地。所有字段先验证再写入当前世界，损坏数据不会部分覆盖战局。

- `tests/skills_check.gd`：111 项通过，覆盖四技能定义、六项属性、减伤、实际击杀士气、重复充能、五类地图效果、行动消耗、效果期限、跨场景属性、存档迁移和损坏档拒绝。
- `tests/skills_runtime.gd`：11 项通过，实际 1920×1080 窗口键鼠验证 Q / Esc / 左键施法、范围预览、AOE / 增益 / 恢复、回合恢复以及所选武将的战斗技能。
- 原战斗规则 37 项、完整战斗操作 13 项、导航 59999 项、经营及存档 77 项均通过。

截图和 JSON 报告位于 `previews/skills/`；导航与经营报告仍位于各自原有路径。实机操作报告含暂停、截图与倍速，不能作为稳定 60 FPS 的性能证明；独立渲染性能报告见 `previews/skills/performance-paced.json`。

## 四技能版历史性能实测（2026-11-17，哪吒新美术接入前）

本机 Intel i7-8750H / AMD Radeon Pro 555X，Godot 4.7.2 Compatibility，实际窗口 1920×1080、1× 速度、目标 60 FPS。独立采样覆盖冲锋、碰撞、自动技能和终结技，不进行截图；满编战斗结束较快，按实际持续时间统计。

| 初始实体数 | 采样时长 | 平均 FPS | 帧间隔 P95 | 帧间隔 P99 |
| --- | ---: | ---: | ---: | ---: |
| 50（每侧 2400 人） | 20.02 秒 | 60.00 | 16.680 ms | 16.739 ms |
| 122（每侧 6000 人） | 8.58 秒 | 56.84 | 23.011 ms | 26.286 ms |

50 实体达到平均 60 FPS；122 实体的密集交战仍未达到目标，不能称为稳定 60。此前两次满编采样约 57.78 / 58.29 FPS，也未达标。当前已缓存伤害飘字排版，并跳过完全收敛的碰撞迭代；122 实体、900 步无渲染规则压力测试从约 2744 ms 降至 2334 ms，战果和最大残余重叠不变。该 CPU 改善没有消除实际窗口的帧间隔尖峰。

飘字使用 Godot [TextLine](https://docs.godotengine.org/en/stable/classes/class_textline.html) 复用已排版的数字，保持原字体、描边、坐标和显示时长。初次优化前报告保留在 `performance-before-text-cache.json`，最终报告为 `performance-paced.json`。
