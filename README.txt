封神 · 九州经营
Godot 4.7.2 可运行原型 / v0.2

在 Mac 上打开
1. 下载本版本的 ZIP 并解压，或切换到 codex/fengshen-settlement-economy 分支。
2. 使用 Godot 4.7 导入同目录的 project.godot，等待首次素材导入，按 F5 运行。
3. 运行不需要网络、插件、Node.js 或额外下载素材。所有中文字体、地图与内景随工程提供。
4. 已在 Godot 4.7.2 stable 官方版、Compatibility 渲染器实测；未在真实 macOS GPU 上测试。

先玩这一条路线
启动后是西岐开局，哪吒、南宫适、黄天化位于关中。
点击右上方“西岐内政”，或直接点击地图上的城市、村庄、关隘、渡口，进入内景。
在西岐选择仓廪南侧空地，再选下方“井田”，右侧会显示成本、产出与邻接加成。
点击“兴建”，结束一次回合，井田竣工。选中井田可升级，二级需两回合，三级需三回合。
点击内景左上方的“灵台 · 待修复”开始修复；竣工后全势力钱帛产出增加 10%。
左下方可切换我方村庄和渡口；它们的地块和工匠独立，花费同一份势力资源。
点击“返回九州舆图”或 Esc 回到大地图，再选择青色格子、点击移动继续行军。

经营系统
125 个据点都有独立建设状态：40 城、27 关、33 村、25 渡口。
内景采用城池、村庄、关隘、渡口四套新绘制背景，不是 125 张独立原画。
城市 19 块建设地、村庄 12 块、关隘 10 块、渡口 7 块；地形资源属性固定、存档可恢复。
城市可同时施工两项，其他据点一项。普通建筑三级：工期 1 / 2 / 3 回合，费用为基础的 1 / 2 / 3 倍。
建造立即从共享府库扣费。新建在竣工后的下一次结算开始生产；升级期间保留原等级产出。
回合顺序：结算当前产出入库 → 推进工程并竣工 → 恢复部队行动力。
失去据点后，其产出和地标效果立即停止，工程暂停；重新占领保留已有建筑和施工进度。
撤工返还一半原始费用，需要再次点击确认。拆除不返资源，需要再次点击确认。

资源与建筑
粮草、木材、金铁、玉石、钱帛、兵员均由我方全势力共享，没有地方仓库和运输限制。
顶部绿色数字是真实的下回合势力产出预测；兵员储备位于内景左下。
井田生产粮草；采木场生产木材；金铁矿场生产金铁；市肆生产钱帛；琢玉坊生产玉石。
仓廪：邻接井田 +25% / +35% / +45%。
民居：邻接市肆 +20% / +30% / +40%。
铸兵坊：邻接采木场和矿场 +20% / +30% / +40%。
军营：每回合生产共享兵员；仅城池与关隘可建。
演武场：邻接军营 +25% / +35% / +45%；仅城池与关隘可建。
丹房：生产玉石，邻接琢玉坊 +25% / +35% / +45%。
阵坛：生产钱帛，邻接生产建筑 +10% / +20% / +30%。
井田在沃土、采木场在林地、矿场在矿脉、琢玉坊在灵地额外 +15%。
六边格相邻才生效。同类加成来源取最高值，不重复叠加；地形与邻接合计上限 60%。
普通产出随建筑等级线性提高。数据与说明位于 data/buildings.json。
补兵：据点须建成军营，部队在本地两步可通行范围内。每次最多补 500 人，消耗等量共享兵员、每人 2 粮草和 1 行动力。
不可隔着未占领据点、山体或封闭渡口补兵；兵力不得超过该部队上限。

封神地名与地标
新战局从西岐开始，朝歌属商。大地图据点改用封神地名和配套扩写地名。
地标均在固定据点，不能搬迁或重复建造：
- 西岐 · 灵台：全势力钱帛产出 +10%。
- 岐山 · 封神台：全势力玉石产出 +15%，解锁全势力丹房与阵坛。
- 朝歌 · 鹿台：全势力钱帛产出 +20%。
- 朝歌 · 摘星楼：每回合声望 +5。
- 乾元山 · 金光洞：全势力玉石产出 +20%，解锁丹房与阵坛。
地标名称、原著回目和每个据点的“原著地名 / 游戏扩写”来源保存在 data/fengshen.json。
九州布局沿用已确认地图，是游戏化地域布局，不宣称复原原著精确地理。地标数值效果为原创玩法。
本版不量产乾坤圈、混天绫、打神鞭等原著独有法宝；尚未接入封神主线和法宝任务。

大地图操作与通行
左键点击部队 / 底部卡片：选中部队。左键点击青色地块：显示金色路线；“移动”或 Enter 执行。
右键点击地块：规划并执行路线。右键 / 中键拖动、WASD、方向键平移，滚轮缩放。
据点内景的“前往附近”返回舆图并规划到相邻陆地；远路分回合继续。
占领需要真实的陆地相邻边及 1 点行动力，不能隔山隔河占领。
普通陆地每格 1 点，已占领渡口过河 2 点；渡船从实际岸边出发，落点是对岸陆地。
非我方城市、关隘、村庄、渡口禁止通行；山脉和水面禁止普通陆军通行。
每步移动前复核占位与据点控制，失守会阻断已规划路线。部队不能重叠。
资源共享不改变上述行军限制。
E 结束回合，Space 定位部队，G 显隐六边格，F 全图，1/2/3 选择部队，C 占领。
F3 为开发用地形覆盖。内景中这些地图快捷键不会穿透到大地图；Esc 返回。
原 MapStitch v5 九区图片、拼接坐标、导航地形数据与 11,875 个六边格保持不变。

存档
顶部“存”或 F5 手动保存；“读”或 F9 读取。行军中禁用存读。
保存资源、声望、全部地块、等级、施工队列、地标、归属、兵力、位置、行动力、回合。
先写临时文件再替换正式存档；读档先完整校验，损坏存档不会部分覆盖当前战局。
兼容 v0.1 行军存档：保留原据点归属与部队，补上默认经营状态和起始府库。
新启动默认开始西岐新战局；需要主动读档恢复。旧存档保留旧归属，因此不等于新的西岐开局。
保存位置仍使用原“山河 · 九州行军”目录：
macOS: ~/Library/Application Support/Godot/app_userdata/山河 · 九州行军/campaign.json
Godot 其他平台通过 user://campaign.json 访问。

工程结构
scripts/settlement_economy.gd   共享府库、建筑、队列、邻接、地标、结算与存档校验
scripts/settlement_view.gd      内景场景、地块、营建目录、详情、工匠与地标界面
scripts/world_model.gd         通行、占领、军队、经营状态与统一存档
scripts/game.gd                主循环、相机、输入、内景切换和行军动画
scripts/hud.gd                 战略 UI 与共享资源栏
scripts/map_layer.gd           六边格可达范围、路线、标牌
assets/interiors/              四类新内景
assets/buildings/              十二类建筑与五个地标透明图层
assets/maps/                   未改动的 MapStitch v5 底图
assets/fonts/                  Noto CJK 中文字体及 OFL 许可
scenes/main.tscn               入口

data/world.json / annotations.json / terrain_mask.png 为原地形数据。
tools/build_world.cjs 是可选离线编译器，只有重新标定通行数据时需要 Node.js 与 sharp。

测试与截图

命令行（第一次先导入素材）：
godot --headless --editor --path . --import
godot --headless --path . --script tests/economy_check.gd
godot --headless --path . --script tests/navigation_check.gd
godot --path . -- --settlement-capture=/绝对路径/经营截图目录
godot --path . -- --legacy-fixture --capture=/绝对路径/通行截图目录
--legacy-fixture 仅给旧行军回归测试保留原起点，不影响正常新战局。
运行自动化 UI 测试时请使用独立测试用户目录，避免覆盖自己的 campaign.json。

当前范围
已可进行建设、升级、邻接布局、地标修复、全势力资源结算、补兵、占领和九州行军。
相邻占领仍直接变更归属，尚未加入战斗、敌方 AI、外交、武将养成或封神主线。
等级和武将四维仍为 UI 占位示例；资源、兵力、行动力、建设和地标均为真实状态。
建筑三级目前共用基础原画，以等级标记与轻微体量变化区分，未制作每级独立美术。
原始地图工具：https://github.com/anan1213095357/MapStitch
内景、建筑、地标、头像与部队为项目生成素材；字体许可保留在 assets/fonts/OFL-and-attribution.txt。
