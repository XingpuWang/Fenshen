# 内景 1080p 帧率实测

2026-11-16。Godot 4.7.2 / macOS / Intel i7-8750H / AMD Radeon Pro 555X / OpenGL Compatibility。实际窗口及渲染纹理均为 **1920 × 1080**，项目目标 60 FPS。

最终配置使用 macOS 完成帧绝对时间节拍器，目标 60 Hz；内置额外限帧等待为 0，VSync 为 0。无障碍保留默认自动模式，本机报告 inactive；没有为最终测试关闭该功能。

|---|---:|---:|---:|---:|---:|
| 大城初始 | 600 | 60.00 | 16.77 | 30.77 | 0 |
| 大城建满 | 600 | 60.00 | 16.77 | 16.79 | 0 |
| 小城建满 | 600 | 60.00 | 16.80 | 16.98 | 0 |
| 村庄建满 | 600 | 60.00 | 16.78 | 16.80 | 0 |

| 渡口建满 | 600 | 60.00 | 16.80 | 25.18 | 0 |
| 大城连续缩放拖动 | 1200 | 60.00 | 16.67 | 16.80 | 0 |
| 每帧切换内景压力测试 | 60 | 60.00 | 19.71 | 19.71 | 0 |
| 返回大地图静止状态 | 600 | 60.00 | 16.78 | 16.81 | 0 |

共采样 5460 帧、约 91 秒（不含预热和截屏）。各场景先预热 60 帧，再测 600 帧；连续缩放拖动测 1200 帧；内景切换测 60 帧。逐帧记录完成绘制后的墙钟时间差，原始数据保存在 `production/performance.json`，并用引擎 FPS 计数交叉核对。截图发生在采样之外。

普通使用场景 P99 在 16.67–16.80 ms。出现两帧超过 25 ms，最长 30.77 ms；本轮没有超过 33.33 ms 的帧。前一轮关隘单次 222.22 ms 尖峰未复现，原始记录保留在 `final/performance.json`，不从历史数据中删除。不能据此保证所有硬件或后台负载下均无卡顿。

## 修正内容

- 内景与战斗覆盖大地图时，隐藏后方世界 CanvasItem；返回时恢复每个对象原先的显隐状态。
- 静止界面按事件更新；缩放拖动不再重新计算整座城的产出。营建、升级、读档和据点切换会使显示缓存失效。
- 大地图静止状态也停止无效重绘，移动、鼠标输入和相机变化仍触发刷新。
- macOS 使用绝对完成帧截止时间补偿已花费的绘制时间；最多预留 2 ms 忙等避免定时器合并产生帧间隔摆动。其他平台继续使用原生限帧。该方式有少量 CPU 开销，未改变模拟步长。

初测（上一版背景、相同 1080p、相同建设负载，未设帧上限）大城建满为 27.49 FPS、缩放拖动 22.46 FPS。中间各轮结果保存在 `baseline`、`cached`、`limited`、`pacing-diagnostic`、`final`。其中短时静态未限帧数字仅代表绘制余量，不作为显示器实际刷新率。

本轮覆盖五类内景与返回大地图静止状态；大地图连续拖动、战斗多人负载属于独立性能项目。首次启动、资源导入与截图耗时不计入稳定帧率样本。

## 复现

使用独立测试存档目录的工程副本运行：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path /tmp/fenshen-validation --resolution 1920x1080 --position 0,25 --script tests/settlement_performance.gd -- --perf-output=/tmp/fenshen-performance --perf-frames=600
```

排查限帧等待时参考了 [Godot macOS 事件循环实现](https://github.com/godotengine/godot/blob/master/platform/macos/os_macos.mm) 与 [原生帧延迟实现](https://github.com/godotengine/godot/blob/master/core/os/os.cpp)。实际结论取自上述本机测量；未断言已确定某一外部应用导致等待。
